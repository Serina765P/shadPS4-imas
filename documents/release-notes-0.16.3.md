**版本号：0.16.3**（基线 0.16.1 + 上游修复移植）
上一版被误标为 0.5，与主线版本号容易混淆；本版起恢复 0.16.x 命名，后续如需对齐主线新特性再单独处理。

自上一版（`v0.5.0-pre`）以来共 24 个提交，按类别说明。

## 1. 修复：两个必定复现的闪退

### 1.1 《偶像大师 星光舞台》地狱特训 Pro
进入 Pro 课程、第 5 名偶像加载完成、`dan_kov_d01/d02` 舞蹈动作刚开始时闪退。

### 1.2 三角光露营区 + medley7《kimi wa relations -mix medley》
relations 前奏结束、进入第一段演出时闪退。

**同一个根因**：该内容在某次顶点取数布局切换后，着色器引用的顶点属性里有一条客户机 V# 是空的
（base 0 / size 0 / format 0）。模拟器把这条属性翻译成 `VK_FORMAT_UNDEFINED`、并以
`VK_NULL_HANDLE` + stride 0 的方式声明 binding——这是非法的 Vulkan 顶点输入状态，驱动在首个使用它的
绘制上算出了野取数地址，设备丢失在下一次 `vkQueueSubmit` 才被报告。

**修复**：`GraphicsPipeline::GetVertexInputs()` 丢弃无法翻译成合法顶点输入的属性（空 V#、0 大小、
`eUndefined`）；被丢弃的属性在建管线与首绘日志里可见。同时修正顶点缓冲的绑定方式（按各自的 binding 号
逐个绑定，不再假设列表位置等于语义序号），索引缓冲按客户机映射长度截断并在无映射时绑零缓冲。

两份崩溃日志里三条可疑假设（几何着色器 `OutputVertices` 超限、描述符复用计数、冷编译/显存）均已被遥测排除：
崩溃管线 `gs = 0x0`；`Reusing … extra image descriptor(s)` 从未出现；同样的冷编译条件现在完整跑通。

## 2. 新增：设备丢失时的自证能力

过去设备丢失只有一句断言。现在：

- 丢失时先落地**飞行记录器**：最近 8 次提交的最后一次绘制状态（管线、图元、索引基址/位宽/索引数、
  vertex buffer 数、被丢弃属性数、gl_NumWorkGroups）写入可读日志，并转储最近 8 个渲染阶段的
  **客户机着色器代码 + SPIR-V** 到 `%APPDATA%\shadPS4\shader\dumps\device_lost\`。
- 随后查询驱动层故障信息（`VK_EXT_device_fault`），最后才走断言——先证据、后崩溃。部分驱动的故障查询会让
  进程直接访问越界，所以它被排在最后，证据不受影响。
- 每条新建图形管线打印 `vs/fs/gs` 哈希与状态摘要，每条新管线的首次绘制打印绘制状态。

## 4. 其他修正

- 着色器重编译：复用缓存阶段时把描述符数组计入 binding 计数（`AddBindings`），并同步作废旧编号编译的缓存。
- 管线键版本 `2 → 3`，作废包含非法顶点输入状态的旧管线缓存。
- 几何着色器 `OutputVertices` 按可移植上限钳制（遥测证明该项不是本次崩溃原因，保留为防御）。
